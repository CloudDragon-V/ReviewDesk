## 3. 应优先修复的实现问题

### 3.1 本地审查问题卡漏显示证据和修改建议

对应要求：任务书“有证据支持的说明和审查建议”；开题报告“潜在问题核查”。

后端Finding实际字段为`evidence`、`recommendation`，导入后直接传给前端。前端却读取`description || explanation`和`suggestion`。因此真实静态发现会显示标题、等级和位置，但缺少证据正文与修改建议。说明书生成器读取的字段正确，所以这不是后端完全没有建议。

证据：[Finding定义](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/models.py:22)、[传出结果](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/workbench.py:160)、[错误字段消费](D:/基于大模型的代码审查辅助工具设计与实现/前端功能/web/src/App.vue:233)。

建议：统一字段契约；用真实静态分析结果做页面断言，确认标题、证据、建议、源码位置全部可见。此项改动小、收益直接，列为第一批。

### 3.2 说明书引用尚不能直接跳转源码

对应要求：任务书第4项任务，以及开题报告第91行的“图中节点、变量事件与说明引用均可关联源码位置”。

报告里已有文件名和行号，但ManualViewer仅渲染Markdown，没有定位事件；manual页也不展示源码侧栏。用户仍需手动切页找文件。图节点和变量的联动已经存在，应复用其定位逻辑。

证据：[说明书组件](D:/基于大模型的代码审查辅助工具设计与实现/前端功能/web/src/components/ManualViewer.vue:20)、[页面集成](D:/基于大模型的代码审查辅助工具设计与实现/前端功能/web/src/App.vue:253)、[模型引用文字生成](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/manual_ai.py:170)。

建议：把引用保存为`revision_id + path + start_line + end_line`，点击时打开对应历史版本的源码片段。验收时必须包含“当前项目已修改，但旧报告仍定位旧快照”的情况。

### 3.3 静态调用关系存在误连和漏连

对应要求：任务书技术指标2；开题报告要求测量调用正确性、覆盖率和未解析项。

本次用当前PythonAdapter解析合成代码，确认两例：

```python
# 漏连：当前结果没有记录 index() 这条可确定的调用。
def index():
    return 0

def run(data):
    del data[index()]
```

```python
# 误连：当前把B类体中的f()解析为A.f，并标为resolved=True。
# 嵌套类体的裸名称不会通过外层类命名空间查找A.f。
class A:
    def f():
        return 1
    class B:
        value = f()
```

证据：[删除语句处理](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/understanding.py:593)、[作用域查找](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/understanding.py:288)。上述样例只被解析，没有执行。

建议：先修复可确定语义的误判和漏判，补回归用例；对动态目标继续保留未知。随后统计调用边precision/recall和未知比例。这比单纯扩大调用图节点数更能支撑课题。

### 3.4 上下文去重不完整，检索效果被补充代码稀释

对应要求：开题报告第87行“在上下文预算内去重、排序”，以及四组上下文对照。

prepare_context先加入检索命中，再加入入口、所有函数和整文件。现有去重只能过滤“新片段完全包含在已有片段内”的情况；若先加入函数，再加入包含该函数的整文件，代码仍重复。

本次复现：命中demo.py的L3-L4后又加入L1-L6，同一行`L3: def compute(x):`在最终上下文出现2次。

此外，生成入口固定使用`strategy="hybrid"`；搜索页虽能切换策略，但生成管线还不能直接完成开题报告要求的四组对照。小样本在预算充足时可能被全部补入，使各检索方案实际发送内容趋同。

证据：[上下文追加与去重](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/manual_ai.py:47)、[固定生成策略](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/workbench.py:174)。

建议：按文件合并/扣除重叠行区间，记录每个片段选入理由、去重前后大小和未覆盖范围；把生成上下文策略设为可配置。实验时明确补充规则，确保各模型组只有上下文选择策略不同。

### 3.5 导出失败可能丢失已经生成的正文

对应要求：异常恢复、失败状态保留、文件占用异常覆盖。

当前save_manual先自动写Markdown文件，再把正文写入SQLite。自动导出失败会阻止正文入库。API用量收据是独立保存的，这是已实现的优点，但已返回的模型正文仍可能丢失。

本次离线故障注入：保存5001字符模拟正文，在文件replace阶段抛PermissionError，随后数据库manuals条数为0。没有发送模型请求。

证据：[保存顺序](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/workbench_store.py:97)、[模型结果暂存及最终保存](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/workbench.py:236)、[现有测试只保证用量保留](D:/基于大模型的代码审查辅助工具设计与实现/其它/tests/test_workbench_v2.py:174)。

建议：优先持久化正文和用量，独立记录导出状态；导出失败允许只重试写文件。数据库自身也不可写时，明确报告恢复能力的边界，不能承诺所有磁盘故障都能恢复。

中断任务另有交互缺口：后端保留interrupted任务，但界面刷新后没有任务历史入口。建议补“进行中/中断/失败任务”列表，能查询已有正文、用量和导出状态，而非要求用户掌握job_id。

## 4. 已有功能需要深化的部分

### 4.1 从“引用存在”推进到“结论能被证据支持”

当前manual_ai.py:153-179检查章节格式与E编号存在，不验证章节内每条断言是否由所引代码支持。引用合法与事实正确在开题报告中已明确区分，因此不宜把缺少全自动语义证明判为违约；真正缺口是还缺独立的语义评价和可核查的结论粒度。

建议把重点结论组织为“结论—源码证据—成立条件—未知项”，区分源码事实、静态条件推演和修改建议。对编造变量值、错误调用顺序、遗漏异常条件分别计分，允许证据不足时明确无法判断。

### 4.2 变量事件已有实现，但跨作用域绑定较粗

赋值、覆盖、累加、容器修改等已经记录；`nonlocal`统一标记为“外层函数（nonlocal）”，尚未链接到具体定义作用域和变量ID。别名、浅拷贝、闭包等部分机制靠源码关联语义提示解释，而不是完整数据流分析。

证据：[作用域记录](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/understanding.py:436)、[语义提示边界](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/semantic_notes.py:1)。

建议先补变量定义位置、所属作用域和读写引用的稳定关联，再考虑有限别名关系。任务书没有要求实时调试器或完整执行轨迹，不必为此运行被审查源码。

### 4.3 长说明书需要验证“帮助理解”，而不只满足字数

现有说明覆盖面广，但最终已知样本回归仍记录可读性均分14.8/20；35—41行样本对应约431—479行说明。此为历史评阅结果，不是本次真人测试结论。

建议将正文安排为整体目的、入口、关键调用、关键状态变化、潜在问题；重复的逐项结构索引放到附录或折叠区。5000字符只是自动保存条件，不应成为生成质量目标。实际效果用理解题正确率和完成时间衡量。

证据：[最终回归评分](D:/基于大模型的代码审查辅助工具设计与实现/其它/evaluation/v02_blind/最终说明匿名回归评分.md:21)。

### 4.4 模型审查建议还没有统一问题列表

新版已有本地静态findings，也在模型章节中讨论风险。模型输出模板中的findings尚未被expand_manual消费，模型建议主要保存在长文里，缺少统一筛选、去重和用户反馈。

建议在说明书之外保留结构化候选问题，关联触发条件、影响、建议及证据。此项是审查产品能力的深化；不能因此把现有系统说成完全没有代码审查。

### 4.5 分析器升级后的旧索引需要更新机制

源码指纹只由language和文件哈希组成。同项目同源码再次导入会直接复用旧revision；即使AST分析器或检索分词规则修正，也可能继续使用旧program_json和索引。已有index_batches记录版本，但尚未成为自动重建判据。

证据：[源码指纹与复用](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/knowledge.py:345)、[索引版本记录](D:/基于大模型的代码审查辅助工具设计与实现/后端功能/reviewdesk/knowledge.py:396)。

建议分别标识源码版本、分析器版本、索引版本、提示模板版本和模型参数；允许对同一源码快照生成新分析批次，同时保留旧报告来源。这是后续改进可复现性的要求，不代表现有源码版本隔离没有实现。

## 7. 建议实施顺序与完成标准

| 顺序 | 工作包 | 完成后应拿到的证据 |
