# 前端技术选型

## 状态

- 选型：**PySide6 + Qt Widgets**
- 状态：技术方案已确定，界面代码尚未创建，依赖尚未安装。
- 核查环境：项目虚拟环境为 Python 3.14.6；2026-09-11 通过 pip 查询到可用的 PySide6 最新版本为 6.11.2。

## 为什么选择 PySide6

PySide6 是 Qt 官方的 Python 绑定，适合本项目这种以 Python 为主、需要打包成 Windows 桌面程序的场景。

主要优势：

1. **与 Python 后端直接连接**：界面和审查逻辑可以在同一进程中通过函数调用、Qt 信号和槽通信，第一版不必增加本地 HTTP 服务。
2. **桌面控件完整**：代码输入框、表格、树形列表、分栏、菜单、状态栏和设置弹窗都有成熟控件。
3. **适合关系图**：`QGraphicsScene` 保存函数、类和模块节点，`QGraphicsView` 负责显示、缩放、拖动和点击交互，适合第一版思维导图式代码关系展示。
4. **避免界面卡死**：DeepSeek 请求和项目扫描可以放入 `QThreadPool` 工作线程，完成后通过信号把结果送回主线程。
5. **能打包为 Windows 程序**：后期可使用官方的 `pyside6-deploy` 生成 Windows 可执行程序。
6. **Python 3.14 可用**：Qt for Python 的发布说明已经明确加入 Python 3.14 支持，当前虚拟环境也能查询到兼容版本。

第一版不选择 React、Vue 或 Electron，因为它们会额外引入 Node.js、前端构建工具和进程间通信。等关系图确实需要复杂的 Web 可视化库时，可以只把关系图页面换成 `QWebEngineView + HTML/JavaScript`，其他页面仍保留 PySide6。

## 页面怎么实现

主窗口使用 `QMainWindow`，左侧放功能导航，右侧用 `QStackedWidget` 切换页面。界面只负责展示与收集输入，审查、关系分析、用量计算和密钥存储由独立服务完成。

| 页面 | 用户操作 | 主要控件 | 调用的后端接口 |
| --- | --- | --- | --- |
| 代码审查 | 选择项目或粘贴代码、开始审查、筛选问题 | `QPlainTextEdit`、`QTableView`、`QSplitter`、`QPushButton` | `ReviewService.review()` |
| 关系图 | 查看模块、类、函数及调用关系 | 自定义 `QGraphicsView`、`QGraphicsScene` | `RelationService.analyze()` |
| 用量统计 | 查看本次和历史 token、费用 | `QTableView`、统计卡片、筛选框 | `UsageService.get_summary()` |
| 设置 | 保存或测试 DeepSeek API Key、选择模型 | `QLineEdit`、`QComboBox`、`QDialogButtonBox` | `CredentialStore`、`DeepSeekClient.check_connection()` |

建议布局：

```text
┌──────────────┬──────────────────────────────────────────┐
│ 代码审查     │ 工具栏：选择项目 / 开始审查 / 导出       │
│ 关系图       ├───────────────────┬──────────────────────┤
│ 用量统计     │ 代码或关系图主区域 │ 问题详情/节点详情    │
│ 设置         │                   │                      │
└──────────────┴───────────────────┴──────────────────────┘
│ 状态栏：当前任务、模型、输入/输出 token、估算费用       │
└─────────────────────────────────────────────────────────┘
```

## 前后端接口边界

这里的“前端”和“后端”先作为同一个桌面进程中的不同模块，而不是两个独立服务器。界面层不得直接拼 DeepSeek 请求，也不得直接操作数据库。

建议的 Python 接口如下：

```python
from pathlib import Path
from typing import Protocol


class ReviewService(Protocol):
    def review(self, request: "ReviewRequest") -> "ReviewResult": ...


class RelationService(Protocol):
    def analyze(self, project_path: Path) -> "RelationGraph": ...


class UsageService(Protocol):
    def record(self, usage: "TokenUsage") -> None: ...

    def get_summary(self) -> "UsageSummary": ...


class CredentialStore(Protocol):
    def save_api_key(self, api_key: str) -> None: ...

    def load_api_key(self) -> str | None: ...

    def delete_api_key(self) -> None: ...
```

界面与控制器之间使用 Qt 信号传递事件：

```python
class ReviewPage(QWidget):
    review_requested = Signal(object)  # 发送 ReviewRequest

    @Slot(object)
    def show_result(self, result: "ReviewResult") -> None:
        """将结构化审查结果更新到问题列表和代码标记中。"""
```

完整调用顺序：

```text
用户点击“开始审查”
    -> ReviewPage 发出 review_requested
    -> ReviewController 在线程池中调用 ReviewService
    -> ReviewService 选择代码上下文并调用 DeepSeekClient
    -> DeepSeekClient 返回经过校验的 ReviewResult
    -> ReviewController 发出 review_finished
    -> ReviewPage 更新问题列表、代码标记、token 和费用
```
