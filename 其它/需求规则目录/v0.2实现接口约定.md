# ReviewDesk 0.2 实现约定（2026-09-29源码修补）

目标：Vue 本地 Web 工作台、SQLite 项目版本知识库、基于代码证据的检索与详细中文代码说明书。Python 首发，其他语言通过分析适配器扩展。保留原 Qt 版与旧数据作为基线。超过 5000 个非空白字符的说明自动写为 Markdown；所有长度都可手动导出。静态分析不得执行用户代码，未知运行时值和动态调用必须明确说明。

## 分工与数据契约

新增 Python 模块位于 `后端功能/reviewdesk`；Vue 在 `前端功能/web`；测试在 `其它/tests`。业务通用模型暂用 JSON 可序列化 dict，入口严格验证。源文件沿用 `models.SourceFile(path, content, sha256)`。

### 语言分析 / 说明书

`languages.get_adapter(language).analyze(sources: list[SourceFile]) -> dict`，`languages.supported_languages() -> list[dict]`。Python 适配器内部使用 AST，不执行源码。

返回 Program 字段：

- `language: "python"`, `analysis_version: "python-ast-2026-09-29"`, `files: [{path, purpose, line_count}]`
- `symbols: [{id, path, name, qualified_name, kind, start_line, end_line, signature, docstring, purpose, parameters: [{name, annotation, default, description}], returns: [{line, expression, description, condition}], steps: [{line, kind, text, condition}], variables: [{name, scope, events: [{line, kind, expression, explanation, condition}]}]}]`
- `calls: [{id, source, target, callee, path, line, resolved, description}]`，source 是 symbol id（模块使用模块符号）；target 为已解析 symbol id 或 null；必须保留未解析调用。
- `entry_points: [{path, line, symbol_id, description}]`, `limitations: [str]`

`manual.build_manual(program: dict, findings: list[dict], project_name: str) -> str` 返回完整中文 Markdown，包含阅读地图、模块职责、入口/顺序、逐函数输入步骤输出调用、变量变化、风险与边界。不虚构实际执行轨迹。`manual.count_characters(text) -> int` 为非空白 Unicode 字符数。

源码引用格式为 `[【path:Lstart–end】](reviewdesk-source:<URL编码的相对路径>?start=<正整数>&end=<正整数>)`，由 `manual.source_reference()` 生成。模型文本不能自行获得可信跳转，必须通过 E 编号校验。前端按报告的 `revision_id` 解析引用，检查文件存在及物理行范围；不回退到当前项目版本。旧报告不自动重写。

### 知识库

`KnowledgeStore(path: Path)` 使用独立 knowledge.db，不修改旧 reports 数据格式。

- `save_revision(project_name: str, sources: list[SourceFile], program: dict) -> dict` 返回 project_id、revision_id、fingerprint；同项目相同内容、语言、分析器版本和索引版本幂等。分析器/索引升级后再次导入生成新版本，不改写历史。无分析器版本的旧适配器按 `unversioned` 处理。
- `list_projects() -> list[dict]`, `list_revisions(project_id: str) -> list[dict]`
- `get_revision(revision_id: str) -> dict` 包含 program、sources:[{path,content,sha256}]、project_id/name、revision_id。
- `search(revision_id: str, query: str, limit: int = 8, strategy: str = "hybrid") -> list[dict]`：结果包含 id/path/start_line/end_line/name/content/score/reason，限定同一版本。使用可解释符号/关键词检索；若加入向量代理须如实标明不是预训练语义嵌入。
- `delete_project(project_id: str) -> None` 级联清理该项目；`compare_revisions(base_id: str, target_id: str) -> dict` 返回 files:[{path,status,diff}]。

### Web API（root 实现，前端遵循）

统一 /api 前缀。GET `/api/bootstrap` 返回 token、languages、models、has_key、version。除 bootstrap 外 API 请求头 `X-ReviewDesk-Token` 使用会话 token；下载链接可用 `?token=`。后端限制回环地址和来源。错误 JSON `{detail: 中文信息}`。

- GET `/api/projects` → `{projects:[{id,name,latest_revision_id,revision_count,...}]}`
- POST `/api/import` JSON `{project_name, language:"python", files:[{path,content}]}` → `{job_id}`
- POST `/api/import-folder` `{path,project_name,language}` → `{job_id}`，本地版用户主动输入路径。
- POST `/api/demo` → `{job_id}`
- GET `/api/jobs/{id}` → `{id,kind,status,progress,message,result,error,created_at,updated_at,usage,request_status}`；成功导入/生成 result 包含 revision_id，生成另含 manual_id/export_status/export_error。
- GET `/api/jobs?limit=50` → `{jobs:[...]}`；limit为1–100，按创建时间倒序，条目同单任务接口。usage未知时为null或actual=false，不代表免费；前端默认展示20项。
- GET `/api/revisions/{id}` → `{revision_id,project_id,project_name,program,sources,findings,...}`
- GET `/api/projects/{id}/revisions` → `{revisions:[{id,...}]}`
- DELETE `/api/projects/{id}` → `{ok:true}`
- GET `/api/search?revision_id=...&q=...&strategy=hybrid` → `{results:[...]}`
- POST `/api/manual` `{revision_id, use_ai:false, model:"deepseek-flash", max_cost_cny:"0.20", focus:"", budget:24000, preview_id:null}` → `{job_id}`；AI 请求必须先预览确认并提交匹配的一次性preview_id。
- POST `/api/manual/preview` 同参数 → `{preview_id,context,evidence,coverage,estimated_cost_cny,estimated_tokens,files,limitations,...}`。coverage条目为 `{path,total_lines,included_lines,omitted_ranges:[{start_line,end_line}]}`；同文件行不重复发送，不能把覆盖范围当作理解准确率。
- GET `/api/manuals/{id}` → `{id,revision_id,markdown,character_count,auto_exported,export_status,export_error,document_path,download_url,mode,usage,limitations,...}`。export_status为 `saved` / `failed` / `not_required`；旧库启动时增量迁移，不重写正文。
- POST `/api/manuals/{id}/export` `{}` → 完整manual对象；只从数据库读取正文重试文件导出，不调用模型、不接受自定义路径。长度不超过5000时维持not_required，可直接下载。
- GET `/api/manuals?revision_id=...` → `{manuals:[...]}`；GET `/api/manuals/{id}/download` 返回 .md。
- GET `/api/compare?base_id=...&target_id=...` → `{files:[{path,status,diff}]}`。
- POST `/api/settings/key` `{key,remember:true}` → `{ok:true,has_key:true}`；DELETE 同路径删除；不返回密钥。
- POST `/api/shutdown` → `{ok:true}`：用户主动退出后台。

UI 核心：项目导入/示例、概览、函数调用图、模块/函数详情、变量赋值与分支、源码定位、详细说明书、版本/检索、设置、失败提示。所有模型/源码内容以安全文本渲染，Markdown 不执行 HTML。说明书可长但不为字数重复灌水。

本地问题卡字段为 `evidence` 与 `recommendation`，不得读取不存在的 `code` / `suggestion`。报告生成先提交完整正文及用量，再进行可选导出；文件导出失败时任务结果仍可成功，但需展示export_error并保留下载/重试。数据库写入失败仍是任务失败，不宣称已保存。
