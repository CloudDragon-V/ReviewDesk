# 统一数据结构设计（待确认）

> 状态：设计稿，尚未实现。  
> 适用范围：第一版 Python 代码审查工具、PySide6 界面、DeepSeek API、SQLite 持久化。  
> 设计目标：界面、静态分析、依赖图、模型调用和数据库共用同一套领域结构，同时不直接信任模型返回值。

## 一、先确认的总体原则

1. 第一版只实际审查 Python，但所有顶层结构保留 `language` 字段，方便以后扩展。
2. 文件路径统一使用“项目根目录相对路径”，分隔符统一为 `/`，不得保存绝对路径或包含 `..`。
3. 行号从 `1` 开始；列号从 `0` 开始，与 Python `ast` 的坐标习惯一致。
4. 所有顶层数据都带 `schema_version`；提示词、技能和模型调用分别记录自己的版本。
5. DeepSeek 返回的是 `ModelFindingCandidate`，不是正式 `Finding`。候选结果只有通过本地验证后才能进入界面和数据库。
6. 金额使用十进制定点数，序列化时使用字符串，不能使用浮点数。
7. 时间统一保存为带时区的 ISO 8601 UTC 字符串，例如 `2026-09-11T08:30:00Z`。
8. 默认不在 SQLite 中长期保存完整源码，只保存路径、哈希、必要证据片段和审查结果。

## 二、稳定枚举

```python
ReviewCategory = Literal["correctness", "redundancy", "optimization"]

```

第一版依赖图只需要实际实现 `imports`、`defines` 和 `calls`，其他关系先保留枚举，不要求立即实现。

## 三、基础结构

### 3.1 SourceSpan：统一源码位置

```python
class SourceSpan:
    path: str
    start_line: int
    end_line: int
    start_column: int | None = None
    end_column: int | None = None
    content_hash: str | None = None
```

约束：

- `path` 必须是项目相对路径，例如 `src/service/user.py`。
- `start_line >= 1`，且 `end_line >= start_line`。
- 列号存在时必须大于等于 `0`。
- `content_hash` 用于判断报告中的位置是否已经因源码修改而失效。

### 3.2 Evidence：问题证据

```python
class Evidence:
    kind: Literal["source_span", "static_rule", "dependency_edge"]
    message: str
    location: SourceSpan | None = None
    excerpt: str | None = None
    rule_id: str | None = None
    graph_edge_id: str | None = None
```

证据必须说明“为什么提出这个问题”，不能只重复标题。`excerpt` 应限制长度，避免数据库保存大段源码。

## 四、模型输出与正式结果分离

### 4.1 ModelFindingCandidate：DeepSeek 候选结果

这是允许模型生成的最小结构：

```python
class ModelFindingCandidate:
    category: ReviewCategory
    severity: Severity
    confidence: float
    title: str
    path: str
    start_line: int
    end_line: int
    symbol: str | None
    trigger: str
    impact: str
    evidence_text: str
    recommendation: str
```

模型不允许生成以下可信字段：正式 ID、指纹、用户处理状态、真实 token、费用、文件哈希、技能版本和来源判定。

### 4.2 Finding：通过本地校验的正式问题

```python
class Finding:
    id: str
    fingerprint: str
    category: ReviewCategory
    severity: Severity
    confidence: float
    title: str
    trigger: str
    impact: str
    primary_location: SourceSpan
    symbol_id: str | None
    evidence: list[Evidence]
    recommendation: str
    source: FindingSource
    skill_id: str | None
    skill_version: str | None
    status: FindingStatus
```

说明：

- `id` 由本地程序生成 UUID。
- `fingerprint` 由“规则/类别 + 文件 + 符号 + 归一化问题特征”计算，用于跨次审查去重。
- `confidence` 范围为 `0.0～1.0`，只表示判断可信程度，不等同于严重等级。
- 正式问题至少要有一条有效证据。
- `suggested_patch` 第一版不放进核心结构；以后确认需要自动修复时再单独设计，避免审查与改写耦合。

## 五、代码与上下文结构

### 5.1 CodeChunk：发送给模型的代码块

```python
class CodeChunk:
    chunk_id: str
    path: str
    language: str
    start_line: int
    end_line: int
    symbol_id: str | None
    content: str
    content_hash: str
    selection_reason: str
```

`selection_reason` 用于论文实验和调试，例如 `changed_code`、`direct_dependency`、`called_symbol` 或 `token_budget_fallback`。

### 5.2 ReviewRequest：一次审查任务

```python
class ReviewRequest:
    schema_version: int
    review_id: str
    language: str
    mode: ReviewMode
    target_paths: list[str]
    selected_categories: list[ReviewCategory]
    user_constraints: list[str]
    max_context_tokens: int
    project_revision: str
```

`project_revision` 优先使用 Git 提交 ID；项目没有 Git 时，使用本地文件清单和内容哈希生成快照 ID。

### 5.3 ContextPackage：最终发送给模型的上下文

```python
class ContextPackage:
    schema_version: int
    review_id: str
    language: str
    repository_tree: list[str]
    primary_chunks: list[CodeChunk]
    related_chunks: list[CodeChunk]
    related_symbol_ids: list[str]
    dependency_edge_ids: list[str]
    user_constraints: list[str]
    omitted_items: list[str]
    estimated_input_tokens: int
```

这里的 `estimated_input_tokens` 是调用前估算值，不能与 API 返回的真实 token 混为一谈。

## 六、项目关系图

### 6.1 GraphNode

```python
class GraphNode:
    id: str
    kind: NodeKind
    name: str
    qualified_name: str
    location: SourceSpan
```

建议采用稳定 ID，例如：

```text
py:module:src.service.user
py:class:src.service.user.UserService
py:method:src.service.user.UserService.create_user
```

### 6.2 GraphEdge

```python
class GraphEdge:
    id: str
    source_id: str
    target_id: str
    relation: RelationType
    certainty: RelationCertainty
    evidence_location: SourceSpan | None
```

`confirmed` 表示 AST 可以直接确认；`inferred` 表示存在动态调用等不确定因素；`unknown` 只用于保留暂时无法解析的关系。

### 6.3 RelationGraph

```python
class RelationGraph:
    schema_version: int
    graph_id: str
    project_revision: str
    language: str
    nodes: list[GraphNode]
    edges: list[GraphEdge]
    limitations: list[str]
```

关系图单独保存和复用，不嵌入每一份 `ReviewResult`，避免报告体积随项目变大。

## 七、模型调用、token 与费用

```python
class TokenUsage:
    input_tokens: int | None
    output_tokens: int | None
    cached_input_tokens: int | None
    reasoning_tokens: int | None
    total_tokens: int | None
    provider_reported: bool

class CostEstimate:
    currency: str
    input_cost: str
    output_cost: str
    cached_input_cost: str
    total_cost: str
    pricing_source: str
    pricing_version: str
    estimated: bool

class ModelCallRecord:
    schema_version: int
    call_id: str
    review_id: str
    purpose: str
    provider: str
    model: str
    prompt_version: str
    skill_id: str | None
    skill_version: str | None
    started_at: str
    duration_ms: int
    status: Literal["completed", "failed", "cancelled"]
    usage: TokenUsage
    cost: CostEstimate | None
    error_code: str | None
```

规则：

- token 优先采用 DeepSeek API 返回的 `usage`；只有拿不到时才标记为估算。
- 费用始终是根据某一价格快照计算出的派生值，所以必须保留价格来源和版本。
- API Key 不进入任何领域结构、日志或 SQLite 表。

class ValidationSummary:

## 九、SQLite 表映射建议

第一版建议使用以下表：

| 表名 | 用途 |
| --- | --- |
| `reviews` | 审查任务与最终状态 |
| `findings` | 正式问题 |
| `evidences` | 每个问题的一到多条证据 |
| `graph_snapshots` | 项目关系图版本 |
| `graph_nodes` | 模块、类、函数、方法 |
| `graph_edges` | 导入、定义、调用等关系 |
| `model_calls` | 每次 DeepSeek 调用、耗时、版本 |
| `token_usages` | API 返回或估算的 token |
| `cost_estimates` | 按价格快照计算的费用 |
| `finding_feedback` | 用户接受、忽略、修复及备注 |

完整源码不单独建表；必要的短证据片段保存在 `evidences.excerpt`。

## 十、本地验证流程

```text
DeepSeek JSON
    ↓ JSON Schema / Pydantic 校验
ModelFindingCandidate
    ↓ 路径、行号、文件哈希、证据、枚举、置信度校验
Finding
    ↓ 去重与用户状态合并
ReviewResult
    ↓
PySide6 界面 + SQLite
```

候选结果应在以下任一情况被拒绝或降级：

- 文件不存在，或路径越过项目根目录；
- 行号超出对应文件范围；
- 文件已经变化，位置哈希无法匹配；
- 没有可核验的证据；
- 类别、严重等级或置信度不合法；
- 与已有问题指纹重复；
- 建议依赖不存在的函数、类、变量或第三方接口。

## 十一、建议确认的两个默认决定

1. 第一版只实现 Python 审查，但数据结构保留 `language`，不提前实现多语言解析。
2. SQLite 默认不保存完整源码，只保存项目相对路径、哈希、短证据片段、审查结果、token 和费用记录。

确认后，再把本设计转换为 Pydantic 模型和 SQLite 表结构；在确认之前不创建业务实现。
