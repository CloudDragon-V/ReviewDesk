# ReviewDesk · 代码审查工作台

基于 Python 3.14、Qt 和 DeepSeek 的 Windows 桌面软件。**0.1.0 实现范围：Python 代码**。无需联网即可进行本地检查和查看关系图；用户主动发送后才调用 DeepSeek。

## 三个文件夹怎么找

本文放在「其它」目录；下文所有项目路径均以最外层项目文件夹为起点。

| 文件夹 | 存放内容 | 常用入口 |
|---|---|---|
| `前端功能/` | 桌面窗口、控件、图标和软件启动入口 | `前端功能/启动软件.cmd`、`前端功能/app.py` |
| `后端功能/` | 代码分析、上下文选择、API、数据和报告服务 | `后端功能/reviewdesk/service.py` |
| `其它/` | **安装包**、免安装运行文件、开发环境、测试、测评、文档和打包工具 | `其它/安装包/`、本说明 |

**给另一台电脑使用：复制 `其它/安装包/ReviewDesk-0.1.0-Setup-win-x64.exe`，双击安装即可。**
`Portable-win-x64.zip` 是免安装版，解压全部文件后打开里面的 `ReviewDesk.exe`；`Source.zip` 是开发源码，不是安装包。

这是同一个 Python 桌面程序按职责分目录；后端随程序在本机运行。目录迁移说明见 `其它/需求规则目录/已实现架构与运行说明.md`，原始盲评证据仍保存在 `其它/evaluation/`。

## 安装与第一次使用

1. 将 `其它/安装包/ReviewDesk-0.1.0-Setup-win-x64.exe` 复制到另一台 Windows 10 1809+ / Windows 11 x64 电脑，双击安装。安装到当前用户目录，不要求管理员权限，也不要求预装 Python、Qt、Git 或 Node。
2. 打开 ReviewDesk，选择「载入示例」→「本地审查」。点击问题查看源码位置、证据与建议。
3. 选择项目目录或粘贴 Python 代码。「代码关系」可缩放、拖动并点击节点定位；图来自静态分析，不能覆盖所有运行时调用。
4. 在「设置」填写自己的 DeepSeek API Key，可保存在 Windows 凭据管理器；连接测试读取余额，不生成收费对话。安装包不包含开发时使用的密钥。
5. 点击 DeepSeek 审查，检查将发送的源码预览、文件范围和费用估算后发送。只发送预算内的片段；不会执行或自动修改源码。
6. 可将问题标记为接受/忽略，导出 Markdown 或 JSON。审查历史和用量保存在 `%LOCALAPPDATA%\ReviewDesk\reviews.db`，报告不保存完整源码，但包含脱敏后的必要证据。

安装包为本地构建，尚未购买代码签名证书。Windows 可能显示未知发布者；发布文件的 SHA-256 校验值见 `其它/安装包/SHA256SUMS.txt`。原版验收记录见 `其它/verification/验收报告.md`，其中旧路径属于当时记录；整理后的检查见 `其它/verification/目录整理验证.json`。另一台实体电脑尚未实测。

## 已实现

- 中文原生 Qt 界面、代码语法高亮与行号、问题筛选、源码定位、证据详情、人工处理状态。
- 有界 Python 项目扫描、AST 本地规则、模块/类/函数定义及可静态定位的调用/导入关系。
- 两种可对比上下文策略：按文件顺序截断、风险位置与依赖关系优先；精确记录实际提交行范围和遗漏情况。
- DeepSeek 综合或分类审查；外部结果的 JSON 结构、路径、行号、严重性、置信度和逐字源码证据校验。
- API 超时、鉴权、余额不足、限流、网络、服务端和响应格式错误处理；失败时保留本地结果及已返回的用量。
- API 返回 token 与本地预算估算分开显示；人民币费用使用有日期、有来源的价格表估算。
- Windows 凭据管理器、SQLite 历史、Markdown/JSON 报告、离线示例、自带运行时的安装包。
- 隐藏合成题库、匿名对比、独立评分和模拟双盲协议。结果与限制见 `evaluation/` 和验收报告。

## 明确边界

- 第一版只分析 `.py`；没有 Java/JS 解析、Git diff 模式、向量数据库、训练模型或自动修复功能。
- 本地规则侧重可解释的局部模式，无法保证所有逻辑错误都被发现；未出现问题不代表程序正确。
- 图不运行代码、不做全程序类型推断，不猜测反射、动态导入和实例方法分派。
- token 预算采用 UTF-8 字节数作为保守代理，不是 DeepSeek tokenizer；费用预检以当前高峰单价做保守估算，不能保证未来平台价格不变。价格核查日期为 2026-09-12。
- 自动脱敏只能识别常见格式。发送前应检查预览；调用模型仍需网络、有效密钥和余额。API 超时后不自动重试，避免重复计费。
- 默认跳过隐藏/生成/虚拟环境目录、常见敏感文件、符号链接/Windows 目录联接、大文件。最多 500 文件、单文件 256 KiB、总源码 8 MiB；遇到边界会显示说明。
- 模拟双盲使用分离的 agent 角色和隐藏身份/答案，不是人类受试者研究，不能据此宣传通用检出率。

## 在 PyCharm 中运行与验证

已有环境：双击 `前端功能/启动软件.cmd`。在 PyCharm 中重新选择解释器 `其它\.venv\Scripts\python.exe`，运行 `前端功能/app.py`。旧 PyCharm 配置已随开发工具移到 `其它/.idea/`，打开最外层目录时需要自行选择上述解释器。

重新建立开发环境时，在最外层项目目录执行（需要 Python 3.14）：

```powershell
python -m venv 其它\.venv
.\其它\.venv\Scripts\python.exe -m pip install -r 其它\requirements-build.txt
$env:PYTHONPATH = "$PWD\前端功能;$PWD\后端功能"
$env:PYTHONIOENCODING = 'utf-8'
.\其它\.venv\Scripts\python.exe -m unittest discover -s 其它\tests -v
.\其它\.venv\Scripts\python.exe 前端功能\app.py
```

离线 UI 测试使用 QtTest，可在 `QT_QPA_PLATFORM=offscreen` 下运行。源码与安装版均支持独立冒烟模式（不调用 API）：

```powershell
.\其它\.venv\Scripts\python.exe 前端功能\app.py --smoke-test 其它\verification\manual-smoke.json --screenshot 其它\verification\manual-desktop.png
```

真实 API 测试只审查合成代码，必须显式开启，密钥从当前用户凭据读取：

```powershell
.\其它\.venv\Scripts\python.exe 其它\scripts\live_smoke.py --allow-paid
```

重新构建：安装 Inno Setup 6.7.3，执行 `powershell -ExecutionPolicy Bypass -File 其它\scripts\build.ps1 -InnoCompiler '你的 ISCC.exe 路径'`（当前电脑已配置编译器，可省略 `-InnoCompiler`）。安装 EXE 生成在 `其它/安装包/`，运行目录生成在 `其它/运行文件/`；再执行 `.\其它\.venv\Scripts\python.exe 其它\scripts\archive_release.py` 更新两份 ZIP 与校验值。PyInstaller 的 Windows 产物需要在 Windows 构建。它将 Python 和 Qt DLL 一起装入目录；不要仅复制目录里的单个 EXE。LGPL 组件以动态库形式分发，可替换并按上述流程重建，许可证见 `其它/licenses/` 与 `其它/THIRD_PARTY_NOTICES.md`。

构建脚本会主动收窄 DLL 搜索 PATH。已修复的一次真实打包失败来自宿主 Poppler 的同名 ICU DLL；不能随意把文档/视频工具的 native 目录加入打包搜索路径。`其它/scripts/verify_bundle.py` 检查外来 ICU 缺席、Qt平台插件、运行时及当前合并修复；`其它/scripts/verify_install.ps1` 是原版隔离安装验收工具，同一用户已正常安装 ReviewDesk 时应避免直接运行该卸载测试。

## 代码从哪里开始看

`前端功能/app.py` 创建窗口 → `前端功能/reviewdesk_ui/ui.py` 收集输入并启动工作线程 → `后端功能/reviewdesk/service.py` 组织任务 → `analysis.py` 解析项目 → `context.py` 选择带行号上下文 → `api.py` 请求 DeepSeek → `service.py` 校验建议 → UI 展示，`storage.py` 保存历史。

核心取舍是把「本地能验证的事实」与「模型提供的判断」分开：AST 提供位置和结构，模型补充语义判断，程序再校验证据。这样可以离线运行、控制开销，并研究上下文策略对质量的影响。

| 想改什么 | 修改位置 | 同步检查 |
|---|---|---|
| 本地检测规则 | `后端功能/reviewdesk/analysis.py` | 相似正确样例与误报回归 |
| 上下文选择/预算 | `后端功能/reviewdesk/context.py` | 实际提交行范围、脱敏、策略对比 |
| 审查重点/输出格式 | `后端功能/reviewdesk/service.py` | `validate_findings` 与失败路径 |
| 模型/价格 | `后端功能/reviewdesk/api.py` | 官方价格、时段、缓存计费测试、UI模型选项 |
| 页面与交互 | `前端功能/reviewdesk_ui/ui.py`、`widgets.py` | QtTest、截图、小窗口及线程关闭 |
| 历史数据 | `后端功能/reviewdesk/storage.py`、`models.py` | schema版本、旧数据兼容、凭据不得进入数据库 |

理解检查：① 为什么模型说有问题还不能直接显示？提示：路径、行号和证据可能是编造的。② 想降低一次请求开销，先改哪里？提示：界面的上下文预算；源码策略在 `context.py`，不应伪造实际 token。③ 图中没有调用边能证明函数没有使用吗？答案：不能，动态调用可能无法静态解析。

更详细的模块边界与当前状态见 `其它/需求规则目录/已实现架构与运行说明.md`。早期草稿保留为设计历史，不能代表当前全部功能。
