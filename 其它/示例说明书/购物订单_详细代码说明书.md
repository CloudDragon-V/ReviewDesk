### 程序解决什么问题

这个程序是一个购物订单教学示例，它把“准备购物项 → 计算金额 → 生成账单文本 → 输出”的流程拆成三个模块。入口模块 main.py 负责准备输入并协调调用；计价模块 pricing.py 负责验证商品数据、累加金额、按会员规则计算折扣；展示模块 presentation.py 负责把计算得到的订单字典转成人类可读的多行收据。程序本身不处理用户输入，商品和会员状态都硬编码在 main() 中，目的是展示模块分工和函数调用链。

### 记账函数 calculate_order：输入、循环与返回

pricing.py 第13行 def calculate_order(items, member=False): 接收商品列表和可选的会员标记。第15行 subtotal = 0.0 初始化累计原价。第16行 details = [] 初始化逐项金额容器。第17-20行是 for item in items 循环：每次迭代第18行调用 validate_item(item) 获得 amount；第19行 subtotal += amount 累加；第20行 details.append({"name": item["name"], "amount": amount}) 把商品名和金额以字典追加到 details。循环结束后第21行 discount = 0.0 初始化折扣。第22行 if member and subtotal >= 30: 同时要求会员为真且原价累计达到30，两个条件都满足时第23行 discount = subtotal * 0.1 计算九折优惠额。第24行 total = round(subtotal - discount, 2) 得到实付额并保留两位小数。第25-26行返回包含 subtotal、discount、total、details 四个键的字典。所有金额变量的赋值和覆盖都受循环次数和 if 条件控制。

### 验证函数 validate_item：逐项金额的来源

pricing.py 第4行 def validate_item(item): 接收单个商品字典。第6-7行检查 item["price"] < 0，如果单价为负数则 raise ValueError("单价不能为负数")。第8-9行检查 item["quantity"] <= 0，如果数量小于等于零则 raise ValueError("数量必须大于零")。两个检查都通过后，第10行 return item["price"] * item["quantity"] 返回该项金额。calculate_order 第18行调用它，所以 subtotal 累加和 details 中的 amount 都来自这个乘积。如果某个商品不满足条件，异常会向上传播，calculate_order 后面的累加、折扣和返回都不会执行。

### 格式函数 format_receipt：如何读取订单字典

presentation.py 第4行 def format_receipt(order): 接收 calculate_order 返回的订单字典。第6行 lines = ["订单清单"] 初始化文本行列表。第7-8行 for detail in order["details"]: 遍历每个明细字典，第8行 lines.append(f"{detail['name']}：{detail['amount']:.2f} 元") 把商品名和保留两位小数的金额追加到 lines。第9行追加 f"原价：{order['subtotal']:.2f} 元"；第10行追加 f"优惠：{order['discount']:.2f} 元"；第11行追加 f"实付：{order['total']:.2f} 元"。第12行 return "\n".join(lines) 用换行符连接所有行并返回。它只读取字段，不重新计算计价规则，因此输出金额完全取决于传入的 order 字典。
