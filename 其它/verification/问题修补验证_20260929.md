额外的配套修补：

- `analysis_version` 与 `INDEX_VERSION` 加入版本指纹。分析器或索引升级后重新导入会生成新快照，不覆盖旧版本；相同源码在相同分析器/索引版本下仍幂等。
- 新增 `GET /api/jobs?limit=50` 和顶部“近期任务与中断记录”，默认显示最近20项任务。已提交但尚未取得用量的请求显示未知，不显示成零费用，不自动重试。
- 新增 `POST /api/manuals/{id}/export`，仅接受空JSON对象，不允许调用者指定任意文件路径。
- 模型不能自行伪造可点击源码协议；仅本地核验通过的E编号可生成链接。嵌套实体编码也做中和，正常Python代码中的 `&` 不被改坏。
- 空文件不伪造可点击的第1行；EOF之后的解析错误保留说明，但不生成越界链接。

## 2. 如何看懂这次修改

源码联动调用链：`manual.source_reference()` → 报告保存 `revision_id` → `renderManual()` 校验并生成按钮 → `ManualViewer` 发送定位事件 → `resolveManualSource()` 读取报告快照 → `SourceView` 高亮实际行。

导出恢复调用链：生成正文 → `save_manual()` 提交数据库 → `export_manual()` 写临时文件并替换目标 → 更新 `export_status`。如果文件写入失败，正文不回滚；下载接口直接读取数据库。点击重试只走 `POST /api/manuals/{id}/export`，不进入 `generate_manual()`。

上下文去重不是删除函数，而是删除重复发送的行。例如已发送某函数的第10–20行，随后补全整个文件时，只追加第1–9行和第21行之后的预算内内容。`coverage` 明确告诉调用方哪些行实际发送、哪些行遗漏。

以后改动时：修改解析语义需要更新 `ANALYSIS_VERSION` 并补AST测试；修改分词/索引语义需要更新 `INDEX_VERSION` 并补版本隔离测试；不要通过覆盖旧快照让旧报告悄悄指向新代码。
